Connect Smena to Codex

Find and read workspace notes directly in Codex. The MCP connection runs on your own computer.

Each employee needs their own token. Sign in to Smena with your own account and start with “Read notes”. You do not need a manager’s token, a Google password or server access.

1. Prepare your computer

Install Codex, Node.js 22 with npm, and Git. Use the Node 22 release line for this repository. Check the versions in PowerShell or a terminal: 

node --version
npm --version
git --version

Open a permanent tools directory and run these commands. Avoid temporary directories: Codex will launch the adapter from this location.

git clone https://github.com/mlnchkdv/smena-manager.git
cd smena-manager
npm ci

If the repository is already installed, open its directory. Run the following commands from the smena-manager root.

2. Create your personal Smena token

  1. Open smena.team and sign in with your own work Google account.
  2. Select the workspace at the top of the navigation menu. The main team workspace is “СМΞНА”.
  3. Open Settings → Integrations. If integrations are disabled, ask the workspace administrator to enable them.
  4. Name the connection, for example Codex — my name, select only “Read notes”, and choose an expiration.
  5. Select “Create token” → “Copy token”. The value is shown only once.

The token belongs to your account and the selected workspace. Read access covers that workspace’s notes; a folder search filter does not restrict token permissions. Never put the token in a chat, Git, or a message to a colleague.

3. Save the token on your computer

node packages/smena-mcp/src/cli.js auth-login --profile codex --browser

The command prints a one-time http://127.0.0.1:… address. Open it in your browser, paste the token into the masked field, and select Connect / Подключить. Close the tab after it confirms the connection. This local form expires after five minutes.

The secret is saved in Windows Credential Manager, macOS Keychain or Linux Secret Service. Do not put it in the Codex configuration file.

Linux: system secret store is unavailable

On Ubuntu, install libsecret-tools with sudo apt install libsecret-tools. Run setup in your regular user session with its keyring unlocked.

4. Add the local server to Codex

First obtain two absolute paths on your computer.

Windows · PowerShell 
(Get-Command node).Source
(Resolve-Path packages/smena-mcp/src/cli.js).Path
macOS and Linux · terminal 
command -v node
node -p "require('node:path').resolve('packages/smena-mcp/src/cli.js')"

In Codex MCP settings, add a server named smena using STDIO. Set the command to the first path. Its arguments are the second path, followed by serve, --profile, and codex.

Alternatively, add a separate block to your user config.toml: Windows — %USERPROFILE%\.codex\config.toml; macOS/Linux — ~/.codex/config.toml. If CODEX_HOME is set, use that directory. Preserve the other settings. 

[mcp_servers.smena]
command = "C:/Program Files/nodejs/node.exe"
args = ["C:/Users/YOUR_NAME/smena-manager/packages/smena-mcp/src/cli.js", "serve", "--profile", "codex"]
startup_timeout_sec = 30
tool_timeout_sec = 60

This Windows example needs both paths replaced with your command results. Forward slashes / are convenient in TOML. On macOS/Linux, supply your own absolute paths too. If mcp_servers.smena already exists, edit that block instead of adding a duplicate.

This is a local STDIO server. Do not configure https://smena.team as an HTTP MCP endpoint.

5. Verify the connection

node packages/smena-mcp/src/cli.js doctor --profile codex

The response should identify the intended workspace and knowledge:read. The command does not print your token.

Reconnect the MCP server in Codex or fully restart the application, then open a new chat and send:

Call Smena’s get_context tool and confirm the connected workspace is “СМΞНА”. Then find the note “TITLE OF A NOTE YOU KNOW” using search_notes and read it with read_note. Do not change anything.

Replace the title with a note you know. Codex may request permission for its first tool call. Long notes are read in bounded fragments; ask it to continue if you need the complete text.

Seeing write tools in the list does not grant write access. The token, your role, and workspace settings determine access. Writing is not needed for this initial connection.

Troubleshooting

Smena tools do not appear in Codex

Check both absolute paths, save config.toml, and remove any duplicate server block. Restart Codex and open a new chat. Run doctor to distinguish a credential problem from a client setup problem. Do not put the token in launch arguments.

Token expired or connection disabled · 401

Create a new personal token in the correct workspace and run auth-login --profile codex --browser again. This replaces the local secret without changing the Codex server block.

Insufficient access · 403

Check your workspace membership, token permissions, and whether an administrator enabled integrations. A token never expands the user’s access.

Wrong workspace or no matching note

Check get_context. To connect another workspace, select it in Smena before creating a separate token. Use a known note title; search does not cross workspace boundaries.

The local setup form does not open

Run the command again: the previous address expires after five minutes. Alternatively, run node packages/smena-mcp/src/cli.js auth-login --profile codex and paste the token at its hidden terminal prompt.

Codex CLI rejects an existing service_tier setting

Update the outdated Codex CLI. This client configuration error is unrelated to your Smena token; connecting Smena does not require changing application model or speed preferences.

Update or disconnect

To update, stop the MCP connection, open the repository directory, and run git pull --ff-only, then npm ci. Reconnect MCP afterwards.

To revoke access, open Settings → Integrations → your connection → Disconnect in Smena. Notes remain in place. You can then remove the local secret: 

node packages/smena-mcp/src/cli.js auth-logout --profile codex

Removing the local secret alone does not revoke the server token. You can share this guide; never share employee tokens.
