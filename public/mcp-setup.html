Подключить Smena к Codex

Находите и читайте заметки своего рабочего пространства прямо из Codex. Подключение работает на вашем компьютере через MCP.

У каждого сотрудника свой токен. Войдите в Smena под своим аккаунтом и начните с права «Чтение заметок». Токен руководителя, пароль Google и доступ к серверу не нужны.

1. Подготовьте компьютер

Нужны Codex, Node.js 22 с npm и Git. Для репозитория используйте ветку Node 22. Проверьте версии в PowerShell или терминале: 

node --version
npm --version
git --version

Откройте постоянную папку для инструментов и выполните команды. Не используйте временную папку: Codex будет запускать сервер из этого места.

git clone https://github.com/mlnchkdv/smena-manager.git
cd smena-manager
npm ci

Если репозиторий уже есть на компьютере, откройте его папку. Следующие команды выполняются из корня smena-manager.

2. Создайте свой токен в Smena

  1. Откройте smena.team и войдите через Google под своим рабочим аккаунтом.
  2. Выберите нужное пространство в верхней части меню. Для основной команды — «СМΞНА».
  3. Откройте Настройки → Интеграции. Если интеграции отключены, попросите администратора пространства включить их.
  4. Укажите название, например Codex — моё имя, оставьте только «Чтение заметок» и выберите срок действия.
  5. Нажмите «Создать токен» → «Скопировать токен». Значение показывается один раз.

Токен привязан к выбранному пространству и вашему аккаунту. Чтение распространяется на заметки этого пространства; выбор папки в поиске не ограничивает права токена. Не отправляйте токен в чат, Git или сотрудникам.

3. Сохраните токен на своём компьютере

node packages/smena-mcp/src/cli.js auth-login --profile codex --browser

Команда покажет одноразовый адрес http://127.0.0.1:…. Откройте его в браузере, вставьте токен в скрытое поле и нажмите Connect / Подключить. После сообщения «Подключено» закройте эту вкладку. Локальная форма действует пять минут.

Секрет сохраняется в Windows Credential Manager, macOS Keychain или Linux Secret Service. В файл настройки Codex его вставлять не нужно.

Linux: не найдено системное хранилище

На Ubuntu установите libsecret-tools командой sudo apt install libsecret-tools. Выполняйте подключение в своей обычной пользовательской сессии с разблокированным хранилищем ключей.

4. Добавьте локальный сервер в Codex

Сначала получите два абсолютных пути на своём компьютере.

Windows · PowerShell 
(Get-Command node).Source
(Resolve-Path packages/smena-mcp/src/cli.js).Path
macOS и Linux · терминал 
command -v node
node -p "require('node:path').resolve('packages/smena-mcp/src/cli.js')"

В настройках MCP приложения Codex добавьте сервер smena с типом STDIO: команда — первый путь, аргументы — второй путь, затем serve, --profile, codex.

Либо добавьте отдельный блок в пользовательский config.toml: Windows — %USERPROFILE%\.codex\config.toml, macOS/Linux — ~/.codex/config.toml. Если задан CODEX_HOME, используйте его каталог. Остальные настройки сохраните. 

[mcp_servers.smena]
command = "C:/Program Files/nodejs/node.exe"
args = ["C:/Users/YOUR_NAME/smena-manager/packages/smena-mcp/src/cli.js", "serve", "--profile", "codex"]
startup_timeout_sec = 30
tool_timeout_sec = 60

Это пример для Windows: замените оба пути результатами своих команд. В TOML удобно использовать прямые слеши /. Для macOS/Linux также укажите свои абсолютные пути. Если блок mcp_servers.smena уже есть, измените его, не добавляя второй.

Используется локальный STDIO-сервер. Адрес https://smena.team не нужно добавлять как HTTP MCP endpoint.

5. Проверьте подключение

node packages/smena-mcp/src/cli.js doctor --profile codex

В ответе должны быть нужное пространство и knowledge:read. Команда не выводит токен.

Переподключите сервер MCP в Codex или полностью перезапустите приложение, затем откройте новый чат и отправьте:

Вызови у Smena инструмент get_context и проверь, что подключено пространство «СМΞНА». Затем найди заметку «НАЗВАНИЕ НУЖНОЙ ЗАМЕТКИ» через search_notes и прочитай её через read_note. Ничего не изменяй.

Замените название на известную вам заметку. При первом вызове Codex может запросить разрешение. Для длинных заметок чтение идёт фрагментами; попросите продолжить, если нужен весь текст.

Наличие инструментов изменения в списке не выдаёт права записи: их определяют токен, ваша роль и настройки пространства. Для начального подключения запись не требуется.

Если что-то не получилось

В Codex нет инструментов Smena

Проверьте абсолютные пути, сохранение config.toml и отсутствие второго блока с тем же именем. Перезапустите Codex и начните новый чат. Команда doctor помогает отделить проблему доступа от настройки клиента. Не добавляйте токен в аргументы запуска.

Токен истёк или доступ отключён · 401

Создайте новый личный токен в правильном пространстве и снова выполните auth-login --profile codex --browser. Это заменит локальный секрет без изменения блока Codex.

Недостаточно прав · 403

Проверьте своё членство в пространстве, права токена и включение интеграций у администратора. Токен не расширяет права пользователя.

Открылось другое пространство или заметка не найдена

Проверьте get_context. Для другого пространства создайте отдельный токен, выбрав его в Smena перед созданием. Используйте точное название заметки; поиск не просматривает чужие пространства.

Не удалось открыть локальную форму

Повторите команду: старый адрес истекает через пять минут. Альтернатива — node packages/smena-mcp/src/cli.js auth-login --profile codex со скрытым вводом токена в терминале.

Codex CLI не понимает существующий параметр service_tier

Обновите устаревший Codex CLI. Эта ошибка чтения настроек клиента не связана с токеном Smena; для подключения не нужно менять настройки моделей или скорости приложения.

Обновление и отключение

Для обновления остановите подключение MCP, откройте папку репозитория и выполните git pull --ff-only, затем npm ci. После этого переподключите MCP.

Чтобы отозвать доступ, в Smena откройте Настройки → Интеграции → своё подключение → Отключить. Заметки останутся на месте. Затем можно удалить локальный секрет: 

node packages/smena-mcp/src/cli.js auth-logout --profile codex

Удаление локального секрета само по себе не отзывает токен на сервере. Эту инструкцию можно пересылать; токены сотрудников — нельзя.
