# UI/UX: база знаний, самостоятельные холсты и граф — 31.10.2026

## Что изменено в этом этапе

Холсты вынесены из вкладок проектов в самостоятельный раздел **«Холсты» / Whiteboards** рядом с закладками. Можно создать холст без проекта либо выбрать проект и наследовать его доступ. Каталог содержит поиск, плитку/список, миниатюры, сортировку и архив с восстановлением. На телефоне вторичные фильтры открываются отдельным окном, а основное содержимое начинается раньше.

Существующие непустые проектные холсты и холсты с историей преобразуются в самостоятельные документы. Пустая техническая заготовка каждого проекта не засоряет каталог. Старые адреса `/project/:key/whiteboard` переводят на перенесённый документ; для проекта без содержимого — в каталог с контекстом проекта. Сохранены история, связанные материалы, персональные раскладки и проверки прав. Новые холсты находятся общим поиском и доступны как отдельный тип в графе и в ссылках на материалы.

Коммиты реализации:

- `d7f291e` — документы, миграция, совместимость записи и серверные права.
- `5b7b56d` — каталог, создание, редактирование, архив, мобильная компоновка и маршруты.
- `23a9601` — граф, поиск, ссылки на материалы, совместимость личного меню и защита архива.
- `70c2bc0` — согласованные RU/EN-подписи и склонения чисел, уточнение регрессионной проверки раскладок.

## Область аудита и доказательства

Production: `https://smena-manager.vercel.app/`, существующая сессия владельца. Изучены каталог и читатель базы знаний, «Вид», граф и его элементы управления, новый каталог и читатель холста, форма создания без применения, переход по прежнему адресу проекта. Проверка не меняла содержимое рабочих заметок, холстов, файлов и права команды. Временно менялся личный язык интерфейса.

Размеры production в CSS px: **320×740, 390×845, 767×1024, 844×390, 1366×767, 1920×1080**. Автоматическая матрица использует 768×1024 вместо округлённого 767 px. Это браузерные размеры, а не испытания реальных телефонов. Реальные iOS/Android по-прежнему недоступны.

Измерения RU:

- Каталог холстов начинает показывать карточки около **208 px** от верхнего края при 320/390 px; в production видны два существующих холста. Рабочие материалы не использовались для создания тестовых записей.
- Меню «Вид» базы знаний при 390×845 занимает примерно **669 px** по высоте; при коротком экране имеет внутреннюю прокрутку. Переполнения всей страницы по горизонтали в матрице не обнаружено.
- Граф на телефоне начинается примерно с **322 px** от верха окна. В альбомном режиме часть рабочей области требует вертикальной прокрутки. Это вопрос удобства, даже когда горизонтального переполнения документа нет.
- Читатель заметки корректно занимает ширину 390 px, но пустые секции и повторяющийся заголовок Markdown расходуют место. Во время публикации панель обновления перекрывает значительную часть нижней области читателя.

Завершающий проход production: RU и EN проверены на всех шести размерах для меню базы знаний, каталога холстов, содержимого перенесённого холста и графа. Горизонтального переполнения документа не обнаружено. Форма создания проверена при 320 px в обоих языках и закрыта без применения. Старый адрес `/smena/project/prj/whiteboard` перевёл на `/smena/whiteboard/phkbu52`; существующий холст показал **3 карточки и 2 связи**. Оба существующих холста появились в выборе материалов графа; переход из графа открыл самостоятельный документ. Язык возвращён на русский, индикатор — «Сохранено», временная вкладка закрыта, размер браузера восстановлен.

На телефонах панель холста занимала около **111 px**; при 844×390 рабочая область высотой 320 px начиналась около 178 px и уходила ниже экрана. Это подтверждает приоритет режима фокуса. Неправильные числовые формы, замеченные в новом каталоге, исправлены и повторно проверены: «3 карточки · 2 связи». Ни одной тестовой записи на основном сайте агент не создавал.

Автоматические проверки: **593/593** серверных/shared тестов. Сквозные сценарии нового раздела и JSON-обмена прошли в Chromium, Firefox и WebKit (**6/6**); проверены создание, сохранение/обновление, переименование, архив/возврат, общий поиск, переход из графа и отсутствие закрытого холста у другого участника. Отдельно прошли история с восстановлением, множественное выделение, новый набор вкладок проекта и прежний полный сценарий холста. Личные раскладки также прошли отдельную регрессию. Начальные сбои проверок были связаны с повторным использованием старых фикстур и неоднозначным селектором меню; после исправления подготовки данных и селектора затронутые сценарии повторно пройдены. Все эти записи и восстановления выполнялись на изолированной локальной базе.

## English handoff: standalone whiteboards

The new workspace section uses `whiteboards[]` core documents: `id`, `name`, `desc`, optional project association, author/timestamps, `archived` and a version-1 `whiteboard` payload. UI routes are `/whiteboards` and `/whiteboard/:id`; history is `GET /api/whiteboards/:id/versions`. Boards without a project are shared within the current workspace; project-associated boards inherit current project ACLs. Existing project associations are immutable through the ordinary edit form/API, preventing accidental disclosure. Archive is recoverable; arbitrary hard removal through workspace snapshots is rejected.

`migrateProjectWhiteboards` is idempotent and creates documents only for nonempty legacy boards or boards with history. `legacyProject` is server-derived. The old project field is temporarily a compatibility alias; `mergeWhiteboards` bridges old and new clients and rejects divergent simultaneous legacy edits. History still supports old records and the former project history endpoint. The alias duplication is an explicit transitional limitation, not a second editable source of truth. Backups retain the entire logical document model and private history.

Whiteboards are now an entity kind in Graph, manual/material links and workspace search. Material cards keep identities only. New references require current read access; private project data is filtered out of another member’s snapshot, graph and history endpoint. Snapshot revision, replacement hash and restoration checks remain in force. Named layout storage retains its old `project` key as an opaque board identity to preserve existing layout preferences.

Current scalability limits: the catalog renders at most 50 cards initially, thumbnails show at most 40 nodes and 60 edges, and bodies still travel in the core snapshot. The existing per-board limits and overall sync limit remain. No production large-dataset benchmark or physical iOS/Android test is claimed. See the numbered Russian backlog for the next 12 priorities and measurable acceptance criteria.

Проверки качества: ESLint, Prettier, контроль CSS-токенов и production-сборка пройдены. Начальный JavaScript — 537,8 КиБ при неизменном бюджете 600 КиБ. Логи и изображения сохраняются локально в `output/playwright/`; они не содержат секретов и не добавляются в Git. Это проверка наблюдённых сценариев и локальных контрактов, а не гарантия отсутствия любых дефектов.
