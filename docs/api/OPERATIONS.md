# Эксплуатация API и MCP Smena

## Включение пространства

В настройках нужного пространства откройте «Интеграции». Администратор может
независимо включить интеграции, изменение заметок и доступ к файлам. Исходное
состояние каждого пространства — выключено. Участники создают собственные
интеграции в пределах текущей роли; viewer получает только чтение.

Токен привязан к одному пользователю и одному ID пространства. Для другого
клиента или пространства создайте отдельный токен. Название, фильтр папки и slug
не являются границей доступа. Токен видит все доступные ему заметки пространства;
к файлам дополнительно применяются текущие права проекта.

Отдельные аварийные выключатели оператора:

```dotenv
SMENA_PUBLIC_API_ENABLED=false
SMENA_PUBLIC_API_WRITE_ENABLED=false
SMENA_PUBLIC_API_UPLOADS_ENABLED=false
```

Первая переменная останавливает весь внешний API. Вторая запрещает изменения,
третья — файловые операции. Переменная со значением `false` имеет приоритет над
настройкой пространства. Обычный вход Google и браузерный API продолжают работать.
Чтобы вернуть штатное управление настройками пространства, уберите соответствующий
аварийный override и перезапустите production штатным скриптом VPS.

## Подключение клиента

Инструкция для Codex и других клиентов находится в
[README пакета MCP](../../packages/smena-mcp/README.md). Пользовательский config
содержит только команду Node, путь к `cli.js` и имя профиля. Токен сохраняется в
системном хранилище секретов и не включается в Git, аргументы команд или ответы MCP.

На Windows после нажатия «Скопировать токен» можно использовать явный режим
буфера обмена вместо скрытого ввода:

```powershell
node packages/smena-mcp/src/cli.js auth-login --profile codex --clipboard
```

Команда сначала проверяет формат токена и доступ к настроенному origin, затем
сохраняет его в Credential Manager. Произвольное содержимое буфера не отправляется
серверу. Режим включается только флагом `--clipboard`; штатный stdio-сервер буфер
обмена не читает. После сохранения очистите буфер и скройте однократный токен на сайте.

Приложение использует стандартный MCP stdio. Удалённый HTTP MCP endpoint в этом
выпуске не предоставляется. REST `/api/v1` нельзя указывать в поле MCP HTTP URL.

## Запись и восстановление после сбоя

Перед изменением прочитайте заметку и её ETag. Каждое намеренное изменение имеет
свой `Idempotency-Key`; MCP использует UUID операции. При timeout сохраняйте ключ,
тело и If-Match. Сервер хранит квитанцию 24 часа и возвращает результат повтора
после повторной проверки доступа. Другой payload с тем же ключом отклоняется.

`412` означает конфликт версии, `428` — отсутствие обязательного условия или
ключа, `429` — исчерпание лимита. Не превращайте конфликт в безусловное сохранение.
После перезапуска MCP используйте `list_recent_operations` и
`get_operation_status`; локальный журнал содержит идентификаторы и hashes без
текста заметок и секретов. Завершённые записи локального журнала очищаются после
окна повторов, неопределённые операции сохраняются до выяснения результата.

Изменение заметки, версия, audit event и квитанция публикуются в одной условной
записи корня. Ошибка записи blob или индекса не публикует частичный результат.
История ограничена 20 версиями; аудит интеграции и квитанции ограничены по объёму.
Серверная версия назначается всем каноническим путям записи. Восстановление копии
меняет поколение ETag и сохраняет актуальные квитанции, поэтому старый клиент не
может повторить уже выполненное создание как новое после восстановления содержимого.

## Передача файлов

Используйте явную команду `upload-local` из инструкции пакета. Она читает указанный
файл, вычисляет SHA-256 потоком и передаёт ограниченные chunks непосредственно в
Drive. Повтор той же команды с тем же UUID и неизменённым файлом сначала проверяет
принятый диапазон. Завершённый файл не передаётся заново.

Вместо JSON с бинарными данными API возвращает `upload_id`. Приватный маршрут
`/uploads/{id}/transport` нужен только локальной команде передачи: URL и ticket
являются секретными возможностями и не попадают в MCP tools/status или обычный
журнал. Завершение сверяет SHA-256 провайдера; отсутствие checksum возвращает
`UPLOAD_CHECKSUM_PENDING`, несовпадение — `UPLOAD_CHECKSUM_MISMATCH`.

Вложения используют существующий проект и папку файлов. Завершение и привязка
повторно проверяют пользователя и проект. Привязка дополнительно требует ETag
заметки, note write и file read. API скачивания поддерживает Range и потоковую
передачу, не помещая файл в ответ модели.

`SHARED_FILE_MAX_BYTES` сохраняет действующий лимит инсталляции; default в коде —
20 ГиБ. Не увеличивайте Nginx JSON body limit ради загрузок: крупные байты идут
отдельно. Перед реальной большой загрузкой проверьте квоту Drive. Отозванный токен
не может завершить или привязать файл. Ранее выданный Drive URL может принимать
байты до собственного истечения; неподтверждённые объекты проходят существующую
сверку и удержание. Отключённый планировщик уведомлений не требуется включать.

## Хранение и диагностика

`smena-manager-integrations.json` хранится отдельно от экспортируемого workspace
содержимого. В нём находятся проверочные hashes токенов, политики, ограниченные
квитанции файловых операций и приватные upload capabilities. В local-режиме файл
создаётся с правами 0600; в Drive используется отдельный приватный объект с CAS.
Содержимое этого файла не включают в пользовательские portable exports и обычные
копии заметок. Его обслуживание относится к учётным данным сервера.

Лимит интеграции — 60 запросов в минуту, счётчик сохраняется между рестартами.
Просроченные записи очищаются при работе реестра; для этого не включается cron.
В серверном журнале `[Integration API]` остаются request ID, шаблон маршрута,
метод, статус и длительность. Query с поисковым текстом, тело, токен и upload URL
не логируются. Для диагностики ошибки клиент передаёт оператору код и request ID.

## Выпуск и откат

CI выполняет серверные проверки, сборку и браузерную приёмку до публикации на VPS.
После публикации проверяют сначала отдельное тестовое пространство: чтение,
создание, повтор, конфликт, историю, загрузку и отзыв. UI проверяют на RU/EN при
ширинах 320, 390, 768, 1366 и 1920 px. Основное пространство включают отдельно.

При проблеме используйте выключатели, отключите интеграцию или её запись. Уже
созданные заметки и файлы сохраняются. Для отката приложения выбирайте версию,
которая сохраняет новые серверные поля и квитанции; восстановление старой копии
заметок не является откатом API. Восстановление содержимого не восстанавливает
отозванные токены. Google OAuth, Drive credentials, пауза уведомлений и права
участников не меняются этим выпуском.
