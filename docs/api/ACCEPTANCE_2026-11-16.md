## Подключение Codex

Для выбранного пользователем основного пространства **«СМΞНА»** создан отдельный
профиль `codex` с единственным scope `knowledge:read`. Срок действия токена —
**14.02.2027**. Запись заметок и доступ к файлам этого пространства выключены.
Секрет сохранён в Windows Credential Manager; пользовательский `config.toml`
содержит только абсолютные пути к Node и локальному MCP-серверу.

Проверены запуск именно настроенной команды, стандартное stdio-соединение,
`get_context`, имя пространства, scope и список из 18 tools. Второй независимый
SDK-клиент также проходит контрактный тест. Это проверка протокола и настройки;
вызов инструментов моделью внутри интерфейса Codex в этой сессии не проверялся.
Для появления нового сервера в уже открытом Codex требуется переподключить MCP
или начать новую сессию после перечитывания конфигурации.

В установленном CLI обнаружена отдельная несовместимость с уже существующим
`service_tier = "default"` в пользовательской конфигурации. Для проверки
`codex mcp get smena --json` использован разовый override `service_tier="fast"`;
остальные пользовательские настройки не менялись. Сам stdio-сервер от этого
параметра не зависит.

## Проверка на smena.team

Запись проверена только в ранее согласованном личном пространстве
**«ТЕСТ A/F 05.11»**, через отдельную однодневную интеграцию:

- создание заметки через настоящий MCP stdio и чтение сохранённого Markdown;
- кириллица, emoji, таблица, code fence и wiki-ссылка;
- повтор того же UUID возвращает ту же заметку;
- сохранение с актуальным ETag, отклонение старого с `NOTE_VERSION_CONFLICT`;
- чтение списка версий и отображение автора вместе с именем интеграции;
- прямая ссылка открывает заметку, в том числе после обновления страницы;
- реальная resumable-загрузка небольшого служебного TXT в Google Drive;
- серверная сверка SHA-256, повтор без повторной передачи файла;
- чтение метаданных, привязка файла к заметке и скачивание Range 0–1023;
- несовпадающий с прежним запросом UUID блокируется локальным журналом.
- отзыв временного токена подтверждён ответом 401; локальная учётная запись
  временного профиля удалена из системного хранилища.
- попытка основного read-only профиля обратиться к другому workspace
  отклонена HTTP 404 до выдачи данных.

При реальной передаче обнаружен дефект, которого не было видно с подменённым
`fetch`: режим `redirect: error` отвергал Drive 308 Resume Incomplete. Клиент
теперь использует ручную обработку, допускает только 308 **без Location** и
никогда не следует перенаправлению. Добавлен тест с настоящим HTTP-сервером.

Уборка выявила несовместимость с прежним режимом библиотеки: он отказывался
сохранять коллекцию при наличии отдельно хранимой заметки. Исправление допускает
полный revision-checked snapshot из legacy GET, проверяет наличие текста,
отклоняет клиентские storage refs и сохраняет внешнее хранение после изменения.
Неизменённые заметки сохраняют ETag и авторство. Отдельный регрессионный сценарий
проверяет чтение, no-op, правку, историю, устаревшую версию и удаление такой
заметки. Профильные 34 теста, включая каталог на 10 001 заметку, прошли.
После публикации повторено удаление той же служебной заметки через русский UI:
конфликт не повторился, интерфейс подтвердил сохранение. Служебные заметка и TXT
перемещены в восстанавливаемую корзину тестового пространства; окончательное
удаление не запускалось. Временная интеграция отключена, постоянная Codex
сохранена. Оба пространства возвращены на русский язык.

## Размеры и языки

Экран интеграций проверен на RU/EN при ширинах 320, 390, 768, 1366 и 1920 px:
без горизонтального переполнения, с мобильными кнопками 44 px. После финальных
изменений повторена вся матрица; геометрия записана в
`../audits/2026-11-16-api-mcp-ui.json`. Проверены маскирование секрета и
мобильная прямая ссылка заметки. Использовались программные размеры Chrome,
а не физические телефоны. CI дополняет проверку критичных сценариев в трёх
браузерных движках на RU/EN и desktop/mobile.

## Локальная надёжность и ограничения проверки

Полный локальный серверный прогон перед финальной приёмкой: **1054 passed,
2 skipped**. Финальная сборка CI для `9dab7552`: **1059 passed, 1 skipped,
0 failed** на Ubuntu/Node 22. После добавления локальной формы и исправления 308 отдельно прошли
новые проверки same-origin/Host/CSRF, одноразового сохранения, повторного ввода,
настоящего 308 и запрета Location. Проверены lint/format затронутых файлов.

Реальные локальные файлы 1 и 5 ГиБ прочитаны и переданы в контролируемый
имитатор провайдера с начальным смещением 128 МиБ и потерянным ответом после
приёма chunk. Максимальный chunk — 8 МиБ, пиковый RSS — около 115 МиБ.
Метрики сохранены в `../audits/2026-11-16-api-mcp-large.json`; воспроизводимый
скрипт — `scripts/check-mcp-large-upload.js`. Это **не** передача 5 ГиБ в Drive:
production проверен маленьким служебным файлом без такого расходования квоты.

Удаление участника, истечение/отзыв токена, чужое пространство, подмена
заголовка, ограничения scopes, конкурентные записи, сбои хранилища, рестарт,
checksum mismatch и потерянный ответ проверяются серверными тестами. Внешний
удалённый MCP/OAuth пока не реализован: другим клиентам доступен тот же stdio
адаптер и REST API по отдельному integration token.

Google-вход и хранилище Drive сохранены. Планировщик и очередь уведомлений
для этого внедрения не включались.

Публичная проверка `/`, `/api/health`, `/api/auth/config` вернула HTTP 200;
защищённые workspace/revision/file-policy маршруты без авторизации — HTTP 401.
