# Проверка подключения Codex к Smena · 17.11.2026

Подключение к основному пространству «СМΞНА» работает с личным профилем
`codex` и единственным scope `knowledge:read`. Новые токены не создавались,
права не расширялись, данные заметок не изменялись.

Проверки:

- Установленный Codex CLI через собственный `app-server` и метод
  `mcpServerStatus/list` обнаружил сервер `smena` и 18 инструментов, в том
  числе `get_context`, `search_notes`, `read_note`.
- Отдельное стандартное MCP stdio-соединение запустило ровно ту команду,
  которая записана в пользовательском блоке Smena, из другого рабочего каталога.
- `get_context` подтвердил workspace `default`, имя «СМΞНА» и read-only scope.
- Поиск нашёл существующую заметку. Повторный поиск по названию вернул ту же
  заметку; её название и содержимое в этот публичный отчёт не включены.
- `read_note` прочитал два последовательных фрагмента по 256 байт. Ограничение
  UTF-8, ETag и hash содержимого согласованы между фрагментами.

Обнаружена и исправлена проблема локальной конфигурации: установленный Codex
CLI 0.121.0 отвергал явно заданное `service_tier = "default"` ещё до загрузки
настроек MCP. Удалена только эта необязательная строка. Семантика прочих
параметров и весь блок Smena сохранены; платный ускоренный режим не включался.
После исправления обычный `codex mcp get smena --json` работает без override.
Пользовательская конфигурация и секреты не добавлялись в Git.

Вызовы моделью в уже открытом чате не проверялись: его набор инструментов был
загружен ранее. Проверены собственный MCP-клиент Codex и фактические операции
поиска/чтения через stdio. Для обновления инструментов в существующем приложении
следует переподключить MCP или перезапустить Codex и открыть новый чат.
