# Повторный глубокий UI/UX-аудит после N01–N24 / Deep production re-audit

**1 ноября 2026 · новый план Q01–Q18, ещё не внедрён.** Проверен авторизованный [основной сайт](https://smena-manager.vercel.app/). Результат: **6 подтверждённых визуальных/текстовых дефектов и 12 предложений по удобству**. Критического блокирования навигации в проверенных сценариях не обнаружено. Код приложения в этом этапе не менялся.

**EN.** This is a new proposed backlog, not an implementation report: six supported presentation/copy defects and twelve usability opportunities. No critical navigation blocker was found in the reviewed flows. Runtime code was not changed.

Предыдущие **N01–N24 уже внедрены и опубликованы**, включая последние три исправления. Их не нужно реализовывать повторно. [Отчёт о публикации и предыдущая приёмка](UI_UX_PRODUCTION_FOLLOWUP_2026-11-01.md). Новый список использует отдельные идентификаторы **Q01–Q18**.

## 1. Основной вывод / Main conclusion

Основная компоновка устойчива: на проверенных размерах нет горизонтального переполнения корневой страницы. Следующий этап должен исправить **читаемость внутри компонентов**, а не снова уменьшать все кнопки. Отсутствие переполнения страницы не обнаруживает наложение текста внутри сжатых кнопок — именно такой дефект найден в режимах редактора.

Самые полезные ближайшие изменения: нормальная ширина режимов заметки, читаемые подписи свойств задачи, двухрядный подвал закладки и сохранение видимой толщины связей холста при Fit. Затем — компактные массовые действия, возврат к месту чтения и более прямой переход от обзора диаграммы к выбранному материалу.

**EN.** Root-level reflow is stable. The next iteration should fix component-level readability rather than shrink every control. Prioritize note-mode labels, task-property labels, bookmark metadata and zoom-independent whiteboard edges; then improve bulk actions and reading/navigation continuity.

Это **замеры состояний, а не 936 независимых функциональных тестов**. Визуально просмотрены ключевые мобильные, ноутбучные и низкие горизонтальные состояния; сохранено 220 локальных PNG, включая повторные снимки.

- В финальной выборке console warning/error нет записей. Это не аудит Vercel runtime-логов, Gmail/push или uptime. Отдельные задержки команд встроенного браузера устранялись чтением свежего состояния; они не посчитаны доказанными ошибками сайта.

Доказательства находятся только локально в `output/reaudit-after24/`: `matrix.json`, `matrix-accepted.json`, `matrix-excluded.json`, `snapshots.json`, `evidence.json`, `console.json`, `restored.json` и PNG. Эти файлы **не входят в Git**, поскольку DOM/снимки могут содержать материалы команды.

Личные язык/тема/вид временно переключались и возвращены; обычное открытие заметок обновляет личный список недавних материалов.

Новые build/lint/server/E2E-прогоны для документационного этапа не запускались; старые результаты не выдаются за новые.

Объём production небольшой: 6 заметок, 7 папок знаний, 2 закладки, 2 холста, 3 активных файла; готовый граф — 28 узлов / 18 связей, заполненный холст — 3 карточки / 2 связи. Рекомендации для больших коллекций опираются на UI и код; новый нагрузочный тест на тысячах материалов не проводился.

This audit does not establish production writes/restores, member/viewer isolation, physical-device gestures, assistive-technology certification or large-workspace performance. Only personal presentation preferences were temporarily changed. Browser-command timeouts were not treated as application defects. Previous automated-test results remain historical.

### Q01 — Режимы редактора / Editor modes

**Факт.** RU, 390 px: кнопка «Редактор» имеет около 43 px внутренней ширины при `scrollWidth` около 62 px; подписи визуально налезают. EN при 320 px: каждому режиму остаётся около 25 px, тексту требуется 35–44 px. Общего overflow страницы нет. Причина подтверждается сжимаемым `.knowledge-editor-mode .seg` в [knowledge-controls.css](../src/styles/knowledge-controls.css).

**Правка и приёмка.** На узкой панели выделить режимам собственную строку или переставить сохранение/инструменты; подписи не обрезаются и не пересекаются на 320/360/390/640 px в RU/EN, включая длинный статус сохранения. Сохранить нажатие, caret и scroll при смене режима; не уменьшать touch-target ниже 44 px.

**EN.** Mode buttons shrink below their text width. Give the mode group adequate space, keep status/tools secondary and test text bounds as well as root overflow.

### Q02 — Подписи задачи / Task labels

**Факт.** На RU 390 px «Исполнитель» распадается на основное слово и одинокую последнюю букву; значение исполнителя справа остаётся коротким. Меню назначения при этом работает. Проверять сетку `.task-properties` и `.kv`, не обработчик назначения.

**Правка и приёмка.** Перераспределить колонки или перейти к подписи над значением на узкой ширине. RU «Исполнитель», «Срок выполнения» и EN labels не ломаются по отдельным буквам; длинное имя не выталкивает действия, все поля остаются доступны на 320/390 px и в landscape.

**EN.** The Russian assignee label breaks awkwardly despite a short value. Fix responsive property-grid allocation without changing assignment behavior.

### Q03 — Подвал закладки / Bookmark footer

**Факт.** На 390 px общий статус обработки обрезан, дата RU переносится на несколько строк, иконка часов оказывается отдельно. EN короче, но статус также усечён. В одной строке конкурируют статус, дата и четыре действия; это видно в [bookmarks.css](../src/styles/pages/bookmarks.css).

**Правка и приёмка.** Разнести сведения и действия на две короткие строки либо убрать второстепенное в меню. Общий статус и личная звезда остаются различимыми; дата читается целиком, действия не прыгают между карточками. Проверить RU/EN 320/390/767 px без уменьшения зон нажатия.

**EN.** Separate readable metadata from the action strip; preserve the distinction between shared processing state and personal favorites.

### Q04 — Рёбра холста / Whiteboard edges

**Факт.** У заполненного холста на мобильном Fit около 21%. SVG path имеет `stroke-width: 2px`, `vector-effect: none` и масштабируется вместе с `.whiteboard-world`: эффективная толщина около **0,42 px**. В тёмной теме измеренный stroke — `rgb(58,57,54)`, линии едва различимы. Это **холст**, а не уже исправленные N07-рёбра графа. См. [project-whiteboard.css](../src/styles/views/project-whiteboard.css) и [whiteboardEdges](../src/views/project-whiteboard.js).

**Правка и приёмка.** Стабилизировать видимую толщину и контраст линий/стрелок в экранных координатах. Проверить масштаб 0.2/0.5/1/2, обе темы, стрелки и выбранную связь. Координаты карточек, данные связи и Undo от изменения камеры не меняются; на большом приближении линия не становится чрезмерно толстой.

**EN.** Whiteboard edges, unlike graph edges fixed earlier, still shrink with the world transform. Maintain readable screen-space strokes and arrowheads without mutating board data.

### Q05 — Подсказка жестов / Gesture copy

**Факт.** Мобильная кнопка «Панорама и масштаб» уже нажата, но соседний текст всё ещё предлагает «Включите перемещение…». EN также показывает неизменное `Toggle to drag or pinch`. Текст в [project-whiteboard.js](../src/views/project-whiteboard.js) не зависит от `navigationMode`.

**Правка и приёмка.** В режиме pan объяснять активную панораму и способ вернуться к прокрутке; в scroll — способ включить управление. Кнопка, `aria-pressed`, подсказка и реальное поведение согласованы в RU/EN. Проверить и Focus, и обычный режим.

**EN.** Guidance should describe the active interaction mode rather than always tell users to enable it.

### Q06 — Account в RU / Account scope in Russian

**Факт.** Настройки → Безопасность аккаунта: при русском интерфейсе область всё ещё называется `Account · …`. В [settings.js](../src/pages/settings.js) используется `tr('Account')`, для отдельного ключа нет русского значения. Составная подсказка форматирования Markdown, напротив, уже переведена — её не нужно чинить повторно.

**Правка и приёмка.** Добавить контекстный перевод «Аккаунт», проверить свернутую и открытую область на RU/EN и не переводить название пространства.

**EN.** Translate the remaining account-scope caption; preserve authored workspace names and already-correct composite tooltips.

### Q07 — Массовые действия / Bulk actions

**Наблюдение.** На телефоне при выборе страницы заметок панель занимает заметную часть экрана; одновременно видны снятие страницы, общий сброс, счётчик, клавиатурная подсказка Shift, перенос и корзина. Действия доступны, но закрывают часть контента.

**Предложение и приёмка.** Счётчик + перенос сделать основными, выбор страницы/сброс/корзину разместить компактнее. Подсказку Shift показывать по способу ввода, а не постоянно на сенсорном экране. Сохранить сообщение о выборе за текущей страницей, защиту корзины и достижимость последней карточки над нижней навигацией. Desktop range-selection N14 остаётся.

**EN.** Reduce mobile bulk-toolbar height while retaining off-page selection disclosure and safe destructive actions.

### Q08 — Место чтения / Resume reading

**Наблюдение.** После перехода оглавлением к последнему разделу длинной заметки scroll был около 5578 px; после закрытия и открытия той же заметки — 0. Это удобство, не потеря текста. Сохранение позиции редактора уже существует и не является этой задачей.

**Предложение и приёмка.** Лично сохранять якорь/относительное место чтения для ограниченного числа заметок, по пользователю и пространству. Поисковый переход к совпадению должен иметь приоритет; дать «К началу». При изменении/удалении документа безопасно восстановить ближайший доступный якорь. Не писать позиции в общий документ и не переносить их между аккаунтами.

**EN.** Restore a bounded, owner/workspace-scoped reading anchor. Search-match navigation takes precedence; editor-position handling remains separate.

### Q09 — Папки в поиске / Folders in search

**Наблюдение.** Текстовый запрос оставляет одну релевантную заметку, но отдельный блок продолжает предлагать три корневые папки независимо от запроса. При большом каталоге этот блок может отодвигать найденные заметки. Сам поиск папок корректно сохраняет цепочку родителей найденной вложенной папки.

**Предложение и приёмка.** Во время текстового поиска компактно отделять релевантные папки от навигации: сворачивать нерелевантный блок либо показывать найденные папки отдельной группой. Не скрывать активный путь, не превращать обычный переход в папку в глобальный поиск и не терять её фильтр после очистки запроса.

**EN.** Keep matching notes prominent and treat unrelated folder navigation as secondary during text search.

### Q10 — Заголовки исходника / Source headings

**Наблюдение.** Для чтения длинного MD есть рабочее оглавление, но Source остаётся одним textarea без переходов по разделам. Поиск нужного участка длинного документа требует ручной прокрутки или перехода через Read.

**Предложение и приёмка.** Добавить компактный список заголовков для Source, переходящий к соответствующему диапазону исходника с сохранением caret/scroll. Использовать устойчивый разбор уже поддерживаемого Markdown; не менять текст, frontmatter, переносы, wiki-ссылки или TXT. Длинные названия должны помещаться на мобильном; TXT не получает вымышленного Markdown-оглавления.

**EN.** Offer heading navigation to source offsets without changing portable Markdown/TXT or introducing a mandatory rich-text conversion.

### Q11 — Из обзора к карточке / Overview to card

**Наблюдение.** Fit на телефоне делает карточки очень мелкими. Полезное «Найти на холсте» уже есть в Outline и правильно центрирует/масштабирует карточку; в панели одиночного выбора Canvas этот переход не представлен.

**Предложение и приёмка.** Дать той же существующей команде доступ из Canvas-selection, например «Показать карточку». Сохранить возврат к Fit; не дублировать механизм позиционирования и не добавлять изменение документа в Undo. Проверить текстовую карточку, связанный материал и большую рамку.

**EN.** Expose the existing Locate command in the Canvas selection bar, making readable zoom discoverable without a detour through Outline.

### Q12 — Поиск списка графа / Graph-list search

**Наблюдение.** В List на 320 px поиск, фильтр и переключатель вида пытаются поместиться в одной строке; полю остаётся около 110 px, в отличие от более удобной полной строки Canvas на 390 px. Поиск доступен, но редактировать длинный запрос неудобно.

**Предложение и приёмка.** При недостатке ширины дать поиску полную строку в обоих видах; фильтры и переключение оставить рядом ниже. Во время ввода/смены вида запрос, caret и результаты сохраняются. Не увеличивать панель на широком экране без необходимости.

**EN.** Apply a useful minimum search width in List as well as Canvas; retain compact desktop controls.

### Q13 — Контекст списка графа / Graph-list context

**Наблюдение.** У проектов заголовок повторяется в подстроке; у закладок тип встречается и в подстроке, и в badge. Клавиатурная навигация стрелками уже есть и работает — её не нужно добавлять заново.

**Предложение и приёмка.** Показывать в подстроке неповторяющийся полезный контекст: путь, домен или связанный проект, если он есть. Не загружать полные документы ради списка. Доступное имя остаётся однозначным для одноимённых материалов; состояние выбора и roving-focus сохраняются после фильтрации.

**EN.** Remove redundant metadata and use already-available meaningful context without hydrating full documents.

### Q14 — Пустые колонки доски / Empty board lanes

**Наблюдение.** Мобильная доска проверенного проекта начинается с пустого Backlog; две задачи находятся в следующей колонке. Навигатор колонок с числами уже есть, но при открытии большая часть первого экрана занята пустой колонкой.

**Предложение и приёмка.** Лично включаемый режим скрытия/сворачивания пустых колонок либо возврат к последней рабочей колонке. Все статусы и создание задачи в пустом статусе остаются доступны; фильтр временно опустевшей доски не создаёт ложное «задач нет». Проверить RU/EN, много статусов и возврат после изменения фильтра.

**EN.** Offer optional empty-lane reduction or restore the last active lane; keep every status and creation path reachable.

### Q15 — Справка клавиатуры / Shortcut reference

**Наблюдение.** На 390 px текстовое описание и сочетание клавиш размещены друг под другом с отступами как у формы; уже несколько общих команд занимают почти весь экран. Эти строки сами не являются touch-кнопками.

**Предложение и приёмка.** Компактная двухколоночная справка, группировка и при необходимости поиск. Сохранить читабельность длинных RU-команд, различие последовательности `G then H` и одновременного сочетания; реальные интерактивные кнопки оставить с нормальными touch-targets.

**EN.** Use a compact reference layout rather than form-row spacing for noninteractive shortcut entries.

### Q16 — Наследование плотности / Density inheritance

**Наблюдение.** Есть общая плотность содержимого в Appearance и отдельные интервалы карточек знаний «это устройство». Во время аудита общая плотность была обычной, карточки знаний — компактными. Это допустимый override: [knowledge.js](../src/pages/knowledge.js) берёт локальное значение перед `S.prefs.density`.

**Предложение и приёмка.** Явно показывать «Как в настройках: …» и активное локальное переопределение, добавить очевидный сброс к наследованию. Не синхронизировать локальный override коллегам и не сбрасывать сортировку/фильтры вместе с плотностью. Объяснение одинаково понятно в RU/EN.

**EN.** Explain global density versus device-specific card spacing and make returning to inheritance explicit.

### Q17 — Счётчики preview / Preview counters

**Наблюдение.** Готовый preview показывает «Файлы на текущей странице результатов · 1 / 1», а ниже — `3 / 3` между предыдущим и следующим файлом. Первый счётчик означает страницу каталога, второй — файл; технически оба корректны, но подпись первого не называет страницу счётчиком. EN столь же неоднозначен. См. [modal-content.js](../src/overlays/modal-content.js).

**Предложение и приёмка.** Явно писать «Страница каталога 1 из 1» и «Файл 3 из 3 на странице», либо скрыть ненужный счётчик единственной страницы. Проверить переход на соседнюю страницу, фильтр, один файл, пустую страницу и PDF (его собственные страницы должны быть различимы). Сохранить ограниченную загрузку и ACL-проверки N20.

**EN.** Name catalog-page and item-position counters separately, including a distinct PDF-page counter when applicable.

### Q18 — Предварительные результаты / Deferred search counts

**Наблюдение.** Полный поиск честно предлагает перейти в Files для полного каталога, но рядом категория показывает `Files 0+`, а общий итог — число с `+`. Это не доказательство отсутствия файлов, однако `0+` легко прочитать как «ничего не найдено».

**Предложение и приёмка.** Для ещё не выполненного файлового поиска использовать понятное «Искать в файлах»/«Не проверено», а не результат с нулём. После явного запроса показывать подтверждённое число/статус ошибки отдельно. Не возвращать полную загрузку каталога при каждом вводе, не терять запрос при переходе и не показывать чужие материалы.

**EN.** Distinguish unqueried file scope from a confirmed zero without undoing on-demand catalog loading or permission checks.

## 5. Порядок внедрения / Delivery order

1. **Читаемость и состояние:** Q01–Q06. Точечные исправления, каждое отдельным проверяемым commit + push. Сначала Q01–Q04, затем текстовые Q05/Q06.
2. **Ежедневная работа со знаниями:** Q07–Q10. Сначала согласовать компактную панель и восстановление позиции; новые настройки личные, текст заметки остаётся переносимым.
3. **Ориентация в диаграммах:** Q11–Q13. Использовать уже работающие Locate, List и bounded DTO, не создавать повторную загрузку полных материалов.
4. **Общая полировка:** Q14–Q18. Сохранить текущие ACL, источники данных и оптимизированные запросы; не объединять счётчики разных сущностей.

**Для каждого пункта:** RU/EN; 320/390 px, граница его breakpoint, ноутбук 1366×767 и низкий landscape; светлая/тёмная тема для изменённых поверхностей; Tab/Shift+Tab/Escape и возвращение фокуса. Для текста проверять реальные границы надписей, не только `documentElement.scrollWidth`. После локальной проверки — основной сайт на опубликованном commit. Записи/восстановление проверять изолированными fixtures; новый production-write сценарий описать отдельно с точными тестовыми материалами и уборкой.

Физическую приёмку телефонов вести отдельным открытым ограничением до появления устройств. Наличие mobile viewport не закрывает эту проверку. Не переписывать существующие успешные N01–N24 сценарии как новые отсутствующие функции.

**EN.** Deliver each item as a small independently verified commit and push. Check affected text bounds, keyboard ownership, both locales/themes and narrow/short viewports, then verify the published production build. Keep physical-device acceptance and production write/recovery testing explicitly separate from this read-only audit.
