# Внедрение UI/UX-аудита от 26 октября 2026

Изменения по всем 20 направлениям [аудита](UI_UX_AUDIT_2026-10-26.md) внесены последовательными коммитами и отправлены в `main`. Ниже перечислены реализованные возможности, результаты текущего прохода и незакрытые ограничения приёмки. Это не утверждение, что приложение проверено на всех устройствах и во всех состояниях.

English summary: changes addressing all twenty audit areas have been implemented and pushed individually. Russian/English layouts, both themes, five viewport sizes, persistence workflows and browser-engine smoke tests were checked. Production checks were targeted and non-destructive. Physical iOS/Android testing, real on-screen keyboard behavior, native browser zoom and approved visual-diff baselines remain outstanding; generated screenshots are evidence, not approved baselines.

Матрица эргономики также проверяет CSS-диагностику масштаба 200% для базы знаний и оформления настроек, взаимодействие с поиском/просмотром и возврат фокуса. Снимки делаются после появления содержимого, не во время восстановления сессии.

Во время разработки найден конфликт экспорта старого helper закладок. Совместимость восстановлена, прежние тесты возвращены и включены в успешный полный прогон. Старый E2E-сценарий базы знаний сначала ожидал кнопку внутри теперь закрытого меню; он исправлен так, чтобы открывать меню как пользователь, а не обходить видимость. Во время окончательного успешного workflow в журнале были ответы `409 REVISION_CONFLICT`: утверждения о сохранении прошли, но это не основание заявлять нулевое количество конфликтов.

### Основной сайт

На [production](https://smena-manager.vercel.app/) выполнены выборочные проверки в авторизованной сессии:

- Русский мобильный календарь: день открывает список, доступна повестка; пересечение панелей не обнаружено, основной ряд задачи около 44 px, document overflow — 0.
- Английский поиск: читаемый Markdown-фрагмент, открывается reader без редактора; закрытие сохраняет запрос и возвращает фокус; очистка работает.
- Файлы: общие панели, тёмная тема, компактная плотность; на 320 px поле поиска 16 px, загрузка около 44 px, горизонтального переполнения документа нет.
- Граф на 320 px: режим фокуса и выход через Escape; изначально полотно не захватывает сенсорные жесты.
- Хронология: финальная правка позиционирования проверена на production в месячном масштабе с датой 01.12.2026; координата даты 627 px, прокрутка 466,875 px (ожидаемое смещение около 160 px), document overflow — 0. Затем возвращены «Сегодня» и недельный масштаб.
- Входящие: скрытие просмотра переживает reload, затем исходный вид восстановлен; строки уведомлений не открывались и прочтение не изменялось.
- База знаний: оба режима папок доступны; после обновления на 390 px общий режим показывает две папки и первую заметку примерно на y=499 px, против примерно 627 px в аудите. Вход сохраняется при reload и изменении размера.

Для локального начального отдельного блока первая заметка получена на y≈405 px при 390 px и y≈262 px при 1440 px. Это другой режим, чем общая сетка с видимыми папками: замеры нельзя считать взаимозаменяемыми или универсальным нормативом.

Существующие заметки, файлы, проекты, права и уведомления команды не изменялись. Временные проверки языка/темы/плотности возвращены к русскому интерфейсу, светлой теме и обычной плотности. Просмотр входящих снова включён; база знаний оставлена в совместном режиме папок и заметок без запроса и выделения.

## Контракт общих UI-слоёв

- `src/ui/collection-layout.js` — структурные обёртки и семантика; аргумент содержимого уже экранирован вызывающим renderer. Не передавать сюда необработанный пользовательский HTML.
- Общие стили контролов и финальный touch-слой определяют размеры действий; стили страницы определяют сетку и размещение, но не должны уменьшать touch-зоны.
- Общая рамка FolderTile остаётся CSS-контрактом существующих renderer, а не новым универсальным JS-компонентом. PageHeader/Toolbar/Selection мигрированы только в затронутых коллекциях.
- Пустые состояния, loading и меню используют существующие примитивы. Полного переписывания всех renderer и CSS не выполнялось; локальные различия страниц не следует удалять без функционального теста.
- Персональные режимы главной и входящих — локальные настройки пользователя/пространства; плотность содержимого — существующая серверная настройка. Не смешивать их механизмы сохранения.

## Как повторить

Обычные проверки: `npm run lint`, `npm run format:check`, `npm run check:tokens`, `npm run test:server`, `npm run build`.

Функциональные браузерные проверки запускаются через существующую изолированную конфигурацию Playwright:

```powershell
npx playwright test tests/e2e/accessibility.spec.js tests/e2e/knowledge-workflows.spec.js
npx playwright test tests/e2e/cross-browser-smoke.spec.js --project=firefox --project=webkit
```

`npm run check:ergonomics` не поднимает сервер самостоятельно: ему нужна отдельная локальная фикстура `Layout QA` на `http://127.0.0.1:5194`, API на 3194 и тестовый профиль, указанный в сценарии. Использовать отдельные каталоги данных и пустые Google/Gmail/Redis-настройки. Сценарий отвергает production-origin; нельзя направлять нагрузочные данные или тестовые учётные записи в рабочее пространство команды.

Локальные журналы и снимки — в игнорируемом `output/playwright/`: `ergonomics26/`, `improve26-knowledge-workflow.log`, `improve26-cross-browser.log`, `improve26-production-final.png`. Они не входят в Git и не являются переносимыми визуальными эталонами.

## Что ещё требует отдельной приёмки

1. Физические iOS Safari и Android Chrome: экранная клавиатура, системное увеличение текста, safe-area, вложенная прокрутка. Мобильный viewport и WebKit на компьютере не заменяют эти устройства.
2. Настоящий браузерный масштаб 200% отдельно от CSS `zoom` и доступность нижних действий с реальной клавиатурой телефона. Поэтому расширенную приёмку пункта 4 нельзя считать полностью закрытой.
3. Утверждение командой небольшого набора визуальных эталонов и последующее pixel-diff сравнение. Сейчас пункт 20 закрыт автоматическими геометрическими проверками и ручным осмотром, но не утверждёнными эталонами.
4. Ручная оценка новой главной участником команды и руководителем; режимы реализованы и локально проверены, пользовательское исследование не проводилось.
5. Большие реальные наборы файлов/закладок и длительная работа: пагинация ограничивает DOM, но не доказывает серверную масштабируемость или отсутствие всех гонок. Этот проход не меняет права, Drive-протокол, фоновые загрузки или резервное копирование.

Эти ограничения явно оставлены открытыми. Для их закрытия не следует расширять production-доступ, изменять материалы команды или выдавать синтетические результаты за реальные устройства.
