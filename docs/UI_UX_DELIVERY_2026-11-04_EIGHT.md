## Production acceptance / Приёмка на основном сайте

The planned CSS viewports were **320×567, 390×844, 767×900, 844×390, 1024×767, 1366×767 and 1920×1080**. Both languages were exercised across this size set, concentrating on the affected surfaces. A further 706×326 observation occurred while calibrating the viewport scale and is recorded by its actual dimensions. This is not every action at every size.

The local matrix recorded **54 observations: 53 ready and one unfinished whiteboard loading state excluded from ready-layout conclusions**. No recorded observation showed root horizontal overflow. Additional final session cleanup verification is described separately; counts are observations, not independent automated test cases. / Незавершённая загрузка холста не считается успешной приёмкой интерфейса.

Concrete results / Подтверждённые результаты:

1. **Settings, RU/EN 844×390:** the results navigation uses its **344 px** container; the list is about **259 px** high and can scroll through all matches. Clear returns a section body about **245 px** high. Focus is `settings-find-mobile`. Broad and empty-result queries were checked; desktop single-result search preserves the normal section layout and returns focus to `settings-find-desktop`.
2. **Note editor, RU/EN 390 and 320 px:** mode/tool area about **68 px**, compared with the audit's **100.6 px**. At 320 px the three mode buttons remain about **58×44 px** each. There is one `[data-knowledge-save-status]` element. Source/Blocks/Read and editor focus were exercised; the production source text was unchanged after mode and wrap changes. A source-heading command reached the corresponding position. The local edited fixture also retained cursor position 61 when toggling wrap.
3. **Folders, RU/EN 320 px:** filter input approximately **240 px** wide, compared with the audit's 144 px; target height remains 44 px. Tools expose both tree commands and count guidance. Searching the existing Cyrillic folder name returned that folder and its descendants after the render settled. An immediate intermediate AX snapshot was not treated as the final search result. / Поиск проверялся после завершения обновления списка.
4. **Files:** the header measures about **44 px** across the inspected sizes. At 320×567 ready file cards begin around **y=310 px** in the current default mobile folder state. At 844×390 the toolbar begins around y=104, folder tiles around y=185 and files around y=326. These are state-specific measurements, not a universal positioning guarantee. Details opens within the viewport, includes saved filters/export access, scrolls when needed and closes with Escape.
5. **Upload destination:** the final RU 390 px project control is about **151 px** wide and visibly shows `3DGS`; its accessible name remains “Upload to project” plus the selected project in the active language. Final RU/EN checks at 320/390 showed no root overflow. / Имя проекта перестало конкурировать с повторной подписью.
6. **Whiteboard:** the mobile toolbar remains about **53 px** high in Canvas and Outline. At 390×844 canvas height remains about **524 px**. At 320 px current-mode text fits, and the RU accessible action reads “Список. Показать холст” in Outline. Both modes were opened and Canvas restored; no card was moved or edited.
7. **Activity:** the reset label is localized. With grouping enabled, Reset filters leaves its checkbox checked; grouping was then returned off. Source events and task content were not edited.
8. **Data transfer:** both rare-operation sections are initially collapsed in the fresh view. Expanded state survives a search-triggered re-render. Scope summaries, recovery attachment limit and guidance, JSON actions and included-data counts remain available in both languages. No backup, export, import or recovery action was run.
