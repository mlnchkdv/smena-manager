# Результаты внедрения повторного аудита Smena Manager

Программные изменения пакета [R1–R14](UI_UX_REAUDIT_2026-10-26.md) внесены и отправлены отдельными коммитами. R2 оказался неточностью аудита: уже работавший сброс страницы сохранён и покрыт тестами. Автоматическая часть R14 расширена; физические устройства, настоящий browser zoom и утверждение визуальных эталонов остаются открытой приёмкой.

English summary: the implementation covers recovery, search, timeline behavior, compact file controls, knowledge navigation, Markdown excerpts, bookmark reading and startup loading. R2 already worked and now has explicit regression coverage. Automated acceptance is expanded to 360 combinations. Physical-device checks and human-approved visual baselines are still pending; they are not reported as completed.

Матрица выполнена на последних UI-изменениях R7; заключительная правка текстов пустой поисковой выдачи и пути в результатах проверена отдельно. Нового полного Firefox/WebKit-прогона в этом этапе нет. Локальная среда использовала Node 23.6.0, хотя проект требует 22.x: поддерживаемую Node 22 нужно сохранять в CI/production, а не менять engines ради локального запуска.

Первый объединённый E2E-прогон дал 2 успешных сценария и сбой измерения фокуса: проверка успевала взять стиль отсоединённого узла во время перерисовки. После ожидания готового раздела и повторного чтения актуального элемента исходные требования к фокусу сохранены, отдельный прогон доступности прошёл. Две ранние попытки расширенной матрицы прервались при навигации во время разработки; окончательный прогон прошёл. Vite теперь игнорирует `.data`, `output` и `.playwright-cli`, чтобы HTML-артефакты тестов не вызывали перезагрузку приложения.

Роли в дополнительном CLI-flow моделируются в изолированном клиентском состоянии. Это не три реальных production-профиля и не замена серверным ACL-тестам. Синтетические заметки и закладки восстанавливаются из исходного snapshot в `finally`, изменения материалов команды не выполнялись.

Дополнительно прошли оба smoke-сценария Firefox и WebKit — 2/2: основной поток задач и адаптивный каркас. Это не полный функциональный прогон всех разделов в этих движках.

## Основной сайт

На авторизованном production подтверждены:

- Папки общей сетки имеют одинаковую высоту около 89 px в контрольном широком окне; раньше третья растягивалась до 168 px.
- Быстрый просмотр открывает чтение без редактора.
- На английском интерфейсе при фактических 390 px панель файлов занимает около 61 px, первая карточка начинается примерно на y=532 px вместо 588 px до доработки. Фильтры доступны, Escape закрывает панель; горизонтальный overflow равен 0.
- В мобильном английском списке хронологии отсутствуют недействующие sort/group-контролы, document overflow равен 0.
- В английских закладках полное описание раскрывается без появления формы редактирования.
- Перезагрузка и изменение размера не сбросили авторизованную сессию.

Язык временно переключался для проверки и возвращён на русский; тема и плотность не менялись. Не выполнялись загрузки/переименования файлов, изменение заметок, восстановление копий, рассылки, изменение прав или прочтения уведомлений команды. Массовые и изменяющие сценарии проверены только в локальной фикстуре.

## Измерение стартового пути

До отложенной загрузки импортных инструментов начальный JS составлял 522,7 KiB, после — 515,1 KiB. Итоговая сборка с дальнейшими UI-уточнениями — около 515,6 KiB. Это снижение на измеренной сборке, не гарантия ускорения любой операции.

Контрольный профиль: localhost production preview, Chromium, CPU 4×, задержка 100 ms, download 200 KiB/s. Одиночные выборки:

| Метрика                          |      До |   После |
| -------------------------------- | ------: | ------: |
| Холодное открытие формы входа    | 1862 ms | 2184 ms |
| От отправки входа до главной     | 1996 ms | 1562 ms |
| Первый переход в знания и reader | 2681 ms | 2738 ms |

Времена меняются в обе стороны; статистически подтверждённого ускорения не заявляется. После оптимизации отдельный прогретый reload главной составил 1397 ms. Предварительный reload из первой выборки не считается сопоставимым warm-эталоном. API/Drive latency production этими локальными числами не измеряется.

## Как повторить новые проверки

Основная матрица: `npm run check:ergonomics`. Нужна изолированная фикстура Layout QA на 5194/API 3194 без Google/Gmail/Redis-ключей, как в предыдущем протоколе. Проверка не поднимает сервер сама.

CLI-flows запускаются в предварительно открытой браузерной сессии:

```powershell
npx --offline --package @playwright/cli playwright-cli --session qa open http://127.0.0.1:5194
npx --offline --package @playwright/cli playwright-cli --session qa run-code --filename scripts/check-r14-flows.js
```

`scripts/check-deployment-flow.js` и `scripts/profile-startup-flow.js` требуют отдельного локального production preview на 5195 с уже авторизованной тестовой сессией для recovery-flow. Profiling flow сам входит по идентификатору локальной фикстуры. Сценарии отвергают другой origin; переносить эти идентификаторы или синтетические данные в production нельзя.

Артефакты в игнорируемом `output/playwright/`: `r14-server-final.log`, `r14-ergonomics-final.log`, `r14-workflows.log`, `r14-accessibility-retry.log`, `r14-flows-final.log`, `r14-deployment.log`, `r13-before.log`, `r13-after.log`, `ergonomics26/`.

## Открытая ручная приёмка R14

1. Просмотреть четыре кандидата из `docs/visual-baselines.json`, утвердить их для фиксированных данных, времени, браузера и размера. Порядок описан в [руководстве эталонов](VISUAL_BASELINES.md). Без такого решения `check:visual` остаётся pending.
2. На реальных iOS Safari и Android Chrome проверить клавиатуру, safe-area, системный размер текста, вложенную прокрутку и доступность нижних действий. Сохранение входа проверяется отдельно после reload и возврата из фона.
3. Проверить настоящий browser zoom 200% отдельно от CSS `zoom`; подтвердить визуальный фокус и навигацию живым screen reader.
4. Расширить UI-приёмку на реальные отдельные viewer/editor/admin-профили во всех разделах. Текущие сценарии не доказывают полный UX всех ролей.

Дополнительное развитие R6 — постраничный альтернативный список графа сверх 250 узлов — не реализовано: сохранён ограниченный граф с фильтрами. Это не полная загрузка каталога и не новый дефект хранения.
