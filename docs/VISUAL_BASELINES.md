# Утверждение визуальных эталонов Smena Manager

`npm run check:visual` сравнивает PNG-кандидаты с утверждёнными изображениями. До утверждения manifest в `docs/visual-baselines.json` имеет `approved: false`, а проверка возвращает код 2. Такой результат нельзя объявлять успешной визуальной приёмкой.

1. Запустить `npm run check:ergonomics` на фиксированной локальной фикстуре. Использовать одинаковые браузер, данные, дату/время, шрифты, размеры и версии зависимостей. Динамическое время на снимках нужно стабилизировать либо осознанно учитывать при review.
2. Просмотреть четыре перечисленных в manifest PNG из `output/playwright/ergonomics26/` в обычном размере. Проверить не только отсутствие overflow, но чтение названий, действия, фокус, первый экран и оба языка.
3. После решения человека скопировать выбранные изображения в `docs/visual-baselines/`. Для каждого вычислить SHA-256 (`Get-FileHash -Algorithm SHA256`) и записать его в соответствующее поле `sha256` manifest. Указать `approvedBy`, `approvedAt` и только затем `approved: true`.
4. Отдельным коммитом сохранить изображения и manifest. Проверить их вместе с diff, не утверждать автоматически по результату теста.
5. Запустить `npm run check:visual`: код 0 — сравнение прошло, 1 — превышен допуск, 2 — приёмка ещё не утверждена. Изменение baseline без совпадающего утверждённого SHA-256 вызывает ошибку.

Изображения отличий находятся в `output/playwright/visual-diffs/`. Сравнение использует pixelmatch threshold 0,1 и допускает не более 0,1% изменённых пикселей. Проверка не меняет эталоны, не копирует production-данные и не подменяет физические устройства или оценку удобства человеком.
