# Внедрение U01–U14 и F01–F12

U02, завершение операций: крестик и Escape во время записи запрашивают паузу после текущего файла и закрывают окно после подтверждения; уже принятые записи остаются в журнале. При смене сессии/пространства чтение исходников прекращается, окно с прежними именами убирается, собственная блокировка операции освобождается. RU 320 / EN 1366: закрытие сохранило по две записи и четыре ожидающих; серверная очередь стала paused. Дополнительно подтверждены отказ до публикации при сбое индекса и изоляция журнала одного пользователя между пространствами (5 серверных тестов).

U01, совместимость холста: при пустом описании холодная карточка материала использует проверенный фрагмент каталога вместо пустого текста. Более свежий загруженный текст имеет приоритет. Три целевые проверки и RU/EN × 390/1366 px прошли: выдержка видна, MD-метаданные скрыты, запросов полных тел для карточки нет.

U02, интерфейс: лениво загружаемая очередь с предварительной проверкой, отдельными ошибками файлов, выбором «копия/пропуск», прогрессом, паузой и возобновлением. Тексты не сохраняются в localStorage; после reload исходники выбираются повторно и проверяются по hash. Локальный Chromium: 7 020 246 байт / шесть TXT/MD, два ошибочных файла исключены, пауза → reload → выбор исходников → завершение, холодный поиск всех шести текстов. RU desktop и EN 390 px; содержимое проверено выбранными чтениями. Дополнительно 779/779 server/shared тестов Node 22, lint, UI-токены и production build прошли; начальный JS 597,7 / 600 KiB. Production повторно вернул 402 DEPLOYMENT_DISABLED.

Источник: [аудит 06.11](PRODUCT_AUDIT_AND_WHITEBOARDS_2026-11-06.md). Пользователь поручил последовательное внедрение всего пакета. В работе различаются реализация, локальная приёмка и production-приёмка; незавершённый этап не считается выполненным.

Текущий срез: U01–U10 реализованы и проверены локально; протокол раздельного хранения U01–U03 остаётся за выключенным по умолчанию rollout-флагом до production-переноса с резервной копией. U11–U14 и F01–F12 ещё не завершены. Выбор провайдера F12 пользователь отложил. Тесты не заменяют production-приёмку. Действующий следующий приоритетный план — в новом повторном аудите; исторические промежуточные ограничения ниже сохраняются как журнал внедрения.

Основной сайт повторно возвращает HTTP 402. Работа продолжается локально с изолированными данными. Реальные устройства, внешние учётные записи и работающее production-окружение остаются отдельными условиями приёмки.

U01, серверная запись: авторизованные GET/PUT каталога сохраняют папки без чтения тел, загружают только изменяемые заметки и проверяют CAS/токены. Восемь целевых проверок пройдены. Это первый серверный этап; последующее подключение браузера и текущие ограничения описаны ниже.

U01, клиентский протокол: добавлены загрузка выбранного тела, ожидание/повтор в читателе, ограниченный кэш (40 тел / 32 MiB), очистка по сессии/пространству и отделение гидратации от правки. Подтверждение первой записи не стирает следующую; холодный черновик не перекрывает непрочитанное удалённое тело. 18 целевых регрессий прошли. Локальный Chromium: каталог 158 заметок без тел, выбранное чтение и edit/reload/reset прошли на RU/EN, 390×844. Режим доступен только при `KNOWLEDGE_CATALOG_ENABLED=true`; по умолчанию выключен, пока не завершены экспорт, корзина, миграция и холодный поиск. Это не завершение U01.

U01, совместимость корзины/экспорта: удаление и восстановление заметок публикуют каталог и корзину одной серверной транзакцией. Новая корзина хранит проверенные ссылки на тела; чтение core скрывает тексты, а обратная запись восстанавливает только канонические ссылки. JSON/ZIP и офлайн-копирование явно загружают нужные тела. Live-вставки показывают ожидание, с общим пределом 12 чтений фрагментов. В гостевом режиме гидратация не считается запрещённой правкой, реальное изменение текста по-прежнему запрещено. 33 целевые регрессии прошли; локальные RU 390 / EN 1366 delete/restore и точность тела приняты. JSON и ZIP скачаны, все 158 текущих заметок содержат полный текст без указателей на незагруженные тела. Миграция и поисковый индекс ещё не завершены; включение по умолчанию не выполнено.

U01, перенос хранилища: добавлены проверяемый план объёма, обязательная свежая копия, порции по три записи, пауза и продолжение. Локально перенесены 157 активных/архивных записей; тела сохранились. Окно принято в RU/EN на 320×567, 390×844, 844×390 и 1366×768 без выхода за экран. Провайдерные проверки подтверждают сохранность файловых указателей и запрет побочных изменений прав/других разделов; standalone backup/restore сохраняет тела. Все 761 серверная проверка и ESLint прошли. Поиск внешних тел ещё требует индекса; общий rollout остаётся выключенным. Production-приёмка недоступна из-за HTTP 402.

F12: пользователь отложил выбор провайдера. Подключение и внешняя отправка документов не включаются; независимый интерфейс и проверяемые черновики остаются в плане.

U07: новые импорты сохраняют исходное имя отдельно от заголовка, поиск находит имя с дефисами/подчёркиваниями и расширением. Имя доступно в сворачиваемых сведениях исходника и JSON/ZIP; пути ОС не сохраняются. При импорте TXT из ZIP больше не разбирается ложный frontmatter. 21 целевая проверка прошла. Локально выполнены импорт, поиск, чтение и reload (RU 390×844 / EN 1366×768), горизонтальный overflow 0; служебная заметка в корзине. У старых заметок утраченное имя не выдумывается. Индекс хранит сжатый нормализованный текст; холодный запрос сканирует подходящие части, а не является позиционным инвертированным индексом.

The catalog list (including table/custom sort), global search and palette use revision-bound server matches; pending, failed and offline-only coverage stay explicit. A 390/1366 px RU/EN browser check found a marker beyond the cold preview with zero original-body requests and zero page overflow. Twenty-two focused search/store tests passed. The persistent compressed index still scans applicable derived parts: it does not yet provide positional posting lists or a production Drive latency guarantee.

# U02 — resumable append protocol (server)

Reviewed manifests and per-file receipts are saved with the canonical root. Membership is checked under the write lock; journals belong to the actor and workspace; source hashes fence reselection. A fresh standalone backup precedes each new job. Accepted files survive cancellation and lost-response retries without duplication. Six 1 MiB notes were imported across provider/store restarts without placing bodies in the root or journal; ownership, revocation, pause, skip and unsafe-name tests passed. Per-file requests retain the 4 MiB transport cap; the UI source cap is 2 MiB/file, 256 MiB/1,000 files per selection.
