# UI/UX audit after Z01–Z08 / Аудит после Z01–Z08

**Date / Дата:** 4 November 2026. **Production:** https://smena-manager.vercel.app/. Baseline application `bc88c54`; application `6acf051` was then published and inspected. **Status:** AA01–AA14 below are a proposed next package, not implemented changes. The separately requested [whiteboard resizing is delivered](WHITEBOARD_RESIZE_2026-11-04.md).

**RU:** Нового блокирующего сбоя P0/P1 в проверенных сценариях не обнаружено. Дальнейшая работа нужна прежде всего в отдельных сценариях: массовые действия и чтение файлов на коротком экране, читаемость общего графа на телефоне, контекст заметки и компактные пустые состояния. Оснований заново переделывать все разделы нет. Пункты ниже — измеренные неудобства и UX-предложения, а не заявление о четырнадцати функциональных поломках.

**EN:** No new P0/P1 blocker was observed in the inspected workflows. The next work should target specific friction: bulk file actions and previews on short screens, mobile graph readability, note context and compact empty states. Another complete redesign is not justified by this evidence. The fourteen items below are usability improvements, not fourteen confirmed functional failures.

**Production findings confirmed beyond the route matrix:**

1. Quoted file search `"ТЕСТ ФАЙЛОВ — 2"` returned **1 / 3**. Unquoted words are AND-ed substring matches across searchable fields: a numeric token can also match a date. This is existing search semantics, not proven search corruption.
2. The TXT preview loaded its body and related project; next/previous controls and download/offline actions were available. At 320 px the navigation buttons started around **y267**, with the footer taking **two 44 px rows**. Primary content competes with substantial context/actions.
3. Selecting the three existing test files exposed a **215.6 px** selection panel at 320×567, occupying approximately **y272–488**. It presented both Download ZIP and Streaming ZIP; the resumable export entry was also available. Selection was cleared without running an operation.
4. At 844×390, with folder cards expanded, the first file started around **y326**. At 320×567 with folders collapsed it started around **y310**. Z05 remains delivered; AA04 is specifically the remaining height-aware folder default, not another general file-header rewrite.
5. The graph contained **28 materials / 18 connections**. A real mouse drag with physics enabled moved the connected component of **6 nodes**. After motion settled, unrelated components stayed in place. Renderer identity `6` and three canvas layers remained unchanged across a later idle/poll observation. This is a small live graph check, not a large-graph benchmark.
6. The mobile global graph fit many small objects into its overview. Existing Pack to screen, Local graph, Focus connections, simplified mode and physics controls are already present; they must not be proposed as missing features.
7. At 1024 px the members table was **880 px** wide inside an approximately **713 px** scrolling container. Root layout was intact, but comparing identity and right-hand fields requires internal horizontal travel.
8. Knowledge body search for a distinctive existing token returned one note. Its summary read **1 of 1**, while six notes existed in the library. This is a result/pagination wording issue, not evidence of deletion. The compact note-type control is already delivered.

## Order and validation / Порядок и проверка

**RU:** Сначала AA01–AA04 — файлы; затем AA05–AA09 — граф и холсты; затем AA10–AA14 — заметки и остальные сценарии. После каждой логической правки — отдельный commit и push. Во всех пунктах проверять русский и английский, 320/390 px и короткий горизонтальный экран; для таблиц — 1024 px, для компоновки — 1366/1920 px. Новые элементы использовать из текущих токенов и компонентов, не добавляя постоянные панели ради редких действий.

**EN:** Implement Files first, Graph/Whiteboards next, then reader and remaining workflows. Commit and push each logical change. Reuse current tokens/components; disclose rare operations rather than adding permanent toolbars. Validate both locales, narrow portrait, short landscape, tablet tables and desktop composition.

For large-data acceptance, use a separate synthetic workspace with many nested folders/files/notes and graph components. Measure search, selection, pagination, scrolling and renderer continuity; do not manufacture a production load test with team data. Current production contains only three files and is not evidence of large-catalog performance.

## What needs no new redesign / Что сохраняем

Notifications already distinguish recorded incidents from current delivery state; older sign-ins are grouped. Settings already use scoped search, compact results and separate recovery/migration disclosures. Project cards are clickable; note types, board favorites, file icons and the collapsed sidebar avatar have prior fixes. Calendar/timeline retain their current task/event semantics. The inspected Bookmarks, team/access settings and ordinary navigation showed no additional blocking UI issue. This does not prove that every mutation or permission combination works.

## Limits / Ограничения

- UI audit used an owner session. Other users' production sessions and write permissions were not impersonated or changed. Server ACL/merge tests passed, but this is not a complete role-based production acceptance run.
- Team notes/files/whiteboards, access settings, delivery jobs, backups and trash were not mutated. Only locale/view/selection state was exercised and locale returned to Russian. Graph drag changed transient view geometry, not source material or a saved named layout.
- Resize persistence was tested against the isolated local API; production controls were checked without resizing real team cards. A cloud write/reload exercise on a disposable board remains a separate acceptance step.
- No real iOS/Android, virtual keyboard, background/lock-screen, screen-reader or sustained large-data benchmark was performed. Browser sizes do not substitute for these checks.
- Build/lint/token checks and **645/645** server/shared tests passed. These results validate the implementation within their scope and do not certify the entire application's UI/UX.
