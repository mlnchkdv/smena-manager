# База знаний: инструменты, шаблоны и командный разбор

18 ноября 2026. Продолжение авторизованного аудита smena.team.

## Осмотр опубликованного пространства

Проверены инструменты библиотеки, шаблоны, теги, типы с черновым полем,
ZIP-архив, офлайн-библиотека, командный разбор, расчёт хранения, проверка
заметки и раскрытие контекста. Поля типа отменены без сохранения.
Публикация ссылок, миграция, импорт и изменения рабочих заметок не выполнялись.

Измерены 12 исходных состояний на 1366×768, 320×567 и 390×320.
Диалоги помещались по ширине, но обнаружены три проблемы использования места.

## Исправления

- **Инструменты.** На ноутбуке действия размещены в две колонки, пояснение
  и создание по типу занимают полную строку. Высота диалога на 1366×768
  уменьшилась с 614,4 до 414,8 px; содержимое больше не требует прокрутки.
  На телефоне сохранена одна колонка. Высота области нажатия «Создать по типу»
  увеличена с 19,6 до 44 px; длинные названия типов переносятся.
- **Шаблоны.** На ноутбуке первые четыре поля размещены попарно; Markdown
  и выбор проекта используют всю ширину. На коротких экранах диалог использует
  всю высоту, а нижние действия имеют меньшие отступы. На 390×320 область
  полей выросла со 115 до 209 px, нижняя панель уменьшилась со 121 до 61 px.
  На 320 px длинные действия продолжают переноситься без обрезания.
- **Командный разбор.** У очереди убраны складывающиеся отступы полей,
  пустого списка и пагинации. От 361 px фильтры состояния и ответственности
  занимают одну строку, на 320 px остаются друг под другом. Высота содержимого
  пустой очереди на 390×320 уменьшилась с 536 до 318 px, на 320×567 — с 536
  до 391 px. Детальная карточка разбора сохраняет свою компоновку.

## Проверка

Изолированное пространство Layout QA, внешние интеграции отключены.
Production-сборка Vite preview; закреплённая полоса прокрутки оверлея учитывает
доступную ширину Windows. Размеры телефона эмулируются в Chromium.

- 50 состояний инструментов, шаблонов и пустой очереди: RU / светлая /
  обычная плотность и EN / тёмная / компактная плотность.
- Восемь размеров: 320×567, 360×640, 390×844, 390×320, 640×768, 641×768,
  844×390 и 1366×768; дополнительно два состояния заполненной очереди.
- Все диалоги находятся в пределах экрана, горизонтальное переполнение — 0 px.
  На ширине до 640 px измеренные элементы управления имеют размер не менее
  44×44 px. Клавиатурный обход остаётся внутри диалога, Escape закрывает его.
- Шесть проверок axe WCAG A/AA без нарушений; исключений JavaScript нет.
- Через интерфейс сохранён синтетический шаблон с длинным названием,
  повторно выбран и использован для создания заметки. Чтение API подтвердило
  точный Markdown и подстановку даты.
- Синтетическая заметка добавлена в командный разбор. Проверены фильтры
  ответственности и состояния, поиск по названию и перенос длинной строки.
  Хеш исходного текста совпал с исходной тестовой копией.
- Шесть серверных тестов шаблонов, типов и правил/хранилища разбора прошли.
  ESLint, Prettier, CSS-переменные, сборка и бюджет JavaScript проверены.

Тестовые записи создавались только в отдельном локальном наборе данных.
Физическая экранная клавиатура и скринридеры не проверялись.
