# Аудит интерфейса Smena Manager и следующий пакет улучшений

Следующий этап — довести поведение компактных действий, чтение документов и работу с поиском. На проверенных мобильных экранах горизонтального переполнения нет, но часть интерфейса всё ещё тратит слишком много высоты на управление. Есть и конкретные ошибки: безымянные кнопки задач, сброс раскрытого описания закладки и неработающие якоря Markdown.

Пакет содержит 11 работ. Он дополняет [предыдущее внедрение](UI_UX_REAUDIT_DELIVERY_2026-10-26.md): исправленные фильтры хронологии, пагинация, загрузочный fallback, поиск по словам, мобильные фильтры файлов и переходы по wiki-ссылкам не объявляются отсутствующими повторно.

Проверяемый коммит: `51c052e`, 26 октября 2026 года. Наблюдения — примерно 20:20–20:40 Europe/Saratov. P1 — основное действие недоступно без угадывания его назначения; P2 — ошибка поведения или существенное затруднение; P3 — развитие удобства. S/M/L — относительный объём, не оценка в днях.

## Что проверено

На авторизованном [основном сайте](https://smena-manager.vercel.app/) проверены база знаний, закладки, глобальный поиск, файлы, граф, список задач и открытая карточка задачи. Контрольные размеры — 1600 × 900 и 390 × 845 CSS px, русский язык, светлая тема. После reload сессия восстановилась; временный мобильный размер снят. Материалы, права, статусы задач и прочтение уведомлений не изменялись.

Локально в отдельной фикстуре проверены русский и английский интерфейсы при 390 × 845 и 1440 × 900: раскрытие описания, длинные пути папок, MD-читатель и мобильный редактор, видимость создания команды для viewer/editor. Синтетический read model восстанавливался после каждого сценария, сохранение этих материалов в API не выполнялось. Дополнительно просмотрены реализации главной, входящих, настроек, хронологии, истории версий и общих компонентов.

Свежие `check:tokens` и `check:bundle` прошли: все ссылки на CSS-переменные разрешаются; имеющаяся сборка содержит 515,6 KiB начального JavaScript при лимите 600 KiB. Новый build, полный серверный набор, матрица 360 сочетаний и Firefox/WebKit в этом аудите повторно не запускались. Это выборочный аудит сценариев и кода, не полная приёмка всех функций приложения.

### N1 Названия и размеры компактных действий задач

В мобильной карточке задачи подпись «Отметить выполненной» скрывается через `hide-m`, а у самой кнопки нет `aria-label`, `title` или tooltip. Значок не даёт доступного имени. В мобильном списке задач также обнаружены безымянные переключатели вида: текст «Список / Доска / Таблица» скрыт тем же способом.

Задать доступные названия независимо от видимости текста, состояния и языка. Для завершения/возобновления использовать разные понятные подписи. Нормализовать компактную кнопку до зоны 44 × 44 px на touch, проверить её соседей и состояние выбранного вида. Не увеличивать все строки и отступы страницы ради одного значка.

Приёмка: RU/EN, открытая и завершённая задача, 320/390/768 px и планшет с coarse pointer. В дереве доступности нет безымянных основных действий; Tab/Enter, фокус и переключение вида работают. При проверке production завершение реальных задач не нажималось.

Код: [drawer-content.js](../src/overlays/drawer-content.js), [tasks.js](../src/pages/tasks.js), [workspace.css](../src/styles/workspace.css).

### N2 Сохранение раскрытого чтения закладки

Новый просмотр полного описания работает, но закрывается после открытия мобильной навигации. [render.js](../src/shell/render.js) заменяет DOM, а `<details class="bookmark-reading-details">` не имеет сохраняемого состояния. На длинном описании это прерывает чтение и меняет высоту карточки.

Хранить раскрытие по идентификатору закладки в UI-контексте пользователя и пространства, сохранять позицию и адресуемый фокус. Для открытой карточки подпись может меняться на «Свернуть описание». В базе знаний уже есть [knowledge-disclosure.js](../src/ui/knowledge-disclosure.js); его подход можно обобщить без введения параллельного механизма хранения.

Приёмка: раскрыть длинное описание → открыть/закрыть навигацию или popover → продолжить с того же места. Проверить RU/EN, viewer, две раскрытые карточки, удаление объекта, смену пространства и unrelated render. Ни раскрытие, ни его восстановление не меняют `is_read`.

Код: [bookmarks.js](../src/pages/bookmarks.js), [bookmarks.css](../src/styles/pages/bookmarks.css), [render.js](../src/shell/render.js).

### N3 Якоря внутри Markdown

Для `[Contents](#setup)` renderer создаёт ссылку с `target="_blank"`, а заголовок `## Setup` получает `<h3>` без `id`. Внутреннее оглавление не может перейти к разделу; ссылка уводит из текущего окна чтения. Это воспроизведено локально в RU/EN, без изменения существующих заметок.

Сделать устойчивые идентификаторы заголовков и переход внутри текущего читателя. Различать внутренние якоря, внешние URL и wiki-ссылки. Обрабатывать кириллицу, одинаковые заголовки, отсутствующий адресат и несколько открытых представлений без конфликта DOM-id. Не передавать такой переход роутеру приложения как новый материал.

Приёмка: длинный импорт MD с оглавлением → нужный раздел → возврат к чтению без новой вкладки. Проверить мобильный reader, live preview и историю версии; фокус и прокрутка относятся к правильному контейнеру.

Код: [knowledge-markdown.js](../src/shared/knowledge-markdown.js), [knowledge-reading.js](../src/ui/knowledge-reading.js), [knowledge-live-preview.js](../src/ui/knowledge-live-preview.js).

### N4 Предсказуемый поддерживаемый Markdown

Контрольный `*italic*` остаётся буквальным текстом. `![Diagram](https://example.test/chart.png)` превращается в `!` и обычную ссылку. Каждая непустая строка становится отдельным абзацем, а вложенные списки теряют уровень. Это влияет на чтение импортированных документов, даже когда импорт и хранение работают правильно.

Определить и реализовать общий поддерживаемый набор синтаксиса для чтения, live preview и истории: абзацы, emphasis, вложенные списки, начальный номер ordered list, ссылки и изображения. Для изображений отдельно определить доступ к вложениям и поведение внешних ресурсов: не начинать автоматически загружать произвольные внешние изображения ради визуального совпадения. Неподдерживаемый ресурс должен иметь понятное представление.

Приёмка: один corpus MD даёт согласованное чтение во всех трёх местах; код и HTML безопасно обрабатываются, исходный MD и TXT не переписываются. Поддерживаемые конструкции перечислены в документации. Это отдельная задача от уже исправленного удаления frontmatter и формирования кратких описаний.

Код: [knowledge-markdown.js](../src/shared/knowledge-markdown.js), [knowledge-live-preview.js](../src/ui/knowledge-live-preview.js), [knowledge-history.js](../src/ui/knowledge-history.js).

### N5 Компактная мобильная шапка поиска

Подсказка о пагинации и две вторичные кнопки делят одну flex-строку. На production 390 px текст подсказки сжимается в узкую высокую колонку рядом с «Показать все файлы» и «Найти в графе». Ниже категории занимают несколько рядов; в контрольной RU-фикстуре их высота 137 px против 91 px в EN.

Оставить запрос основным элементом, категории представить компактной навигацией с видимым активным выбором, а вторичные переходы собрать в подходящее меню или отдельную строку. Сообщение о неполном каталоге показывать рядом с файловой категорией или её результатами. Сохранить понятный путь к полному поиску файлов и доступность категорий с клавиатуры.

Приёмка: 320/390 px, RU/EN, загрузка/ошибка/пустой результат/несколько категорий/следующая страница. На одинаковой фикстуре результаты появляются выше без уменьшения шрифта или зон нажатия. Мобильная категория не теряется за неочевидной прокруткой.

Код: [search.js](../src/pages/search.js), [search-controls.css](../src/styles/search-controls.css), [components.css](../src/styles/components.css).

### N6 Вторичный путь не должен вытеснять результат поиска

Полный путь теперь помогает различать одинаковые названия. Но шесть длинных сегментов в мобильной выдаче занимают большую часть строки результата: около 169 px на один объект, при этом сам заголовок и найденный фрагмент короткие. Переполнения нет, проблема в плотности и иерархии.

Ограничить видимый путь одной-двумя строками, сохранив информативные начало и конец. Полный путь раскрывать доступным способом, работающим без hover. Заголовок и фрагмент совпадения должны оставаться главными; одинаковые конечные имена в разных ветках должны различаться.

Приёмка: 1/6/12 уровней, длинное слово, одинаковые названия, RU/EN, 320/390/1024 px. Полный путь доступен touch и keyboard; визуальный clamp не удаляет контекст из доступного имени. Проверить также карточки заметок, где путь может расти аналогично.

Код: [search.js](../src/pages/search.js), [collection-readability.css](../src/styles/collection-readability.css), [knowledge.js](../src/pages/knowledge.js).

### N7 Локализация системных значений в смешанных строках

В русской production-выдаче у заметки без папки отображается `General`. Строка пути/категории целиком помечена `translate="no"`, хотя `General` — известный системный ключ. Пользовательские имена папок правильно остаются без перевода. В live preview неразрешённой wiki-ссылки используется английский default-tooltip renderer, в отличие от локализованного читателя.

Разделить системные подписи и пользовательский текст на уровне renderer. Переводить только известные встроенные категории, состояния и подсказки; не менять значения хранения или импортированный текст. Передавать одинаковые локализованные параметры в reader и editor preview.

Приёмка: General/Processes, пользовательская категория, папка с английским именем, TXT и wiki-ссылка без цели. На RU нет случайных английских служебных подписей, на EN нет русского fallback. Смена языка не создаёт версию заметки и не переводит материалы команды.

Код: [search.js](../src/pages/search.js), [knowledge-live-preview.js](../src/ui/knowledge-live-preview.js), [i18n.js](../src/core/i18n.js).

### N8 Мобильные режимы исходника и предпросмотра

Сейчас при включении preview мобильный редактор складывает textarea и весь документ друг под другом. Это корректно по ширине, но для сверки длинного текста приходится многократно перемещаться между блоками. Контрольный preview начинается около y=631 и продолжается ниже y=2000.

На узком контейнере дать переключение «Редактор / Предпросмотр» с сохранением курсора, выделения и независимых позиций прокрутки. На широком оставить одновременные колонки. Состояние сохранения и возврат к редактированию должны оставаться доступными в обоих режимах; переключение не должно создавать новую версию само по себе.

Приёмка: длинный MD и TXT, 320/390/768 px, RU/EN, открытая клавиатура, поворот устройства и переход через breakpoint. Черновик и позиция не теряются. Эмуляция размера не закрывает проверку настоящей мобильной клавиатуры.

Код: [knowledge-editor.js](../src/ui/knowledge-editor.js), [knowledge-live-preview.js](../src/ui/knowledge-live-preview.js), [knowledge.css](../src/styles/pages/knowledge.css).

### N9 Компактный массовый выбор в базе знаний

Без выбранных заметок отдельная строка «Выбрать страницу» занимает около 72 px с отступом. Это заметная доля пространства перед папками и первой заметкой. Зона нажатия уже достаточна; уменьшать её обратно до маленькой кнопки не нужно.

Встроить начало выбора в компактную строку списка или отдельный режим выбора. Полную панель количества, переноса и корзины показывать при наличии выбора. Сохранить выбор вне текущей страницы, понятную отмену и компенсацию прокрутки. Оба режима папок и импорт должны остаться доступны.

Приёмка: на исходной production-фикстуре первая заметка появляется выше; установить целевой предел после контрольного макета, ориентир — освободить большую часть этих 72 px. Проверить 0/1/60 выбранных, переход страницы, фильтр, active bulk bar и мобильный нижний dock. Никакое основное действие не перекрывается.

Код: [knowledge-bulk.js](../src/ui/knowledge-bulk.js), [collection-layout.js](../src/ui/collection-layout.js), [workspace.css](../src/styles/workspace.css).

### N10 Видимость действий команды по возможностям роли

Для viewer и editor в боковой панели видна «Новая команда». Нажатие не открывает окно и не сообщает причину: обработчик правильно возвращается для любой роли, кроме admin. Это ошибка обратной связи и согласованности интерфейса, не обход прав. «Новый проект» для viewer уже скрыт — повторно исправлять его не требуется.

Согласовать рендеринг и обработчики с одной проверкой возможностей. Недоступное создание команды скрывать либо объяснять как недоступное действие там, где это помогает. Не оставлять активную кнопку без результата. Серверные проверки сохраняются независимо от оформления.

Приёмка: viewer/editor/admin на десктопе, в мобильном меню и на странице команд. Для admin создание доступно; для остальных нет молча бездействующего контрола. Проверить отозванные права без перезагрузки.

Код: [layout.js](../src/shell/layout.js), [teams.js](../src/actions/teams.js), [members.js](../src/pages/members.js), [shell.css](../src/styles/shell.css).

### N11 Сравнение версии перед восстановлением

История показывает заголовок, время и отрендеренный текст версии. Восстановление же затрагивает также описание, теги, категорию и папку. Эти поля входят в snapshot, но явного списка будущих изменений перед восстановлением нет. Автора версия хранит, однако строка выбора его не показывает.

Добавить компактное «Что изменится»: текст, заголовок и метаданные, автор и время; для длинного текста — раскрываемое сравнение. На телефоне использовать последовательное сравнение, без двух тесных колонок. Если прежняя папка недоступна и будет выбрана корневая, сообщать это до подтверждения. Действующее ограничение размера истории сохраняется.

Приёмка: версия меняет только текст, только папку, только теги либо несколько полей; старая папка удалена; viewer и editor; RU/EN. Просмотр сравнения ничего не записывает. Восстановление на production требует согласованного тестового материала; в текущем аудите оно не запускалось.
